# Orbit 全面体检报告（2026-07）

> 对标 Claude Code 与 OpenAI Codex 的结构化勘察结论：扬长、补短、技术债与优先级。
> 由四个领域小组（智能体运行时 / 模型-工具-MCP / 信任与状态 / 界面与 UX）
> 基于源码证据合成，非营销文案对照。

## 一句话结论

Orbit 的身份成立且难以复刻：**一个运行时 / 三端同步 + 厂商中立 + 崩溃恢复**。
但该身份依赖非前沿模型（DeepSeek / 本地 Ollama）也能稳定完成多步任务，而
harness 的可靠性守卫此前几乎为空；"sandbox" 也名不副实。补短的重点不是复刻
竞品功能，而是把自己已经声明的差异化真正兑现。

## 扬长（真实、该加压的强项）

| 强项                                | 证据                                                            | 竞品对比                   |
| ----------------------------------- | --------------------------------------------------------------- | -------------------------- |
| 崩溃恢复不重放副作用                | `SessionManager.repairInterruptedToolCalls` + 持久 `RunJournal` | Codex/CC 多为无状态 resume |
| 原子持久化                          | `writeJsonAtomically`：fsync → rename → 父目录 fsync + `.bak`   | 超过多数 CLI               |
| 一个 loop 三端同步                  | `setUserInteraction` 切换 + 共享 approval/cancel                | CC 无本地 WebUI 对等物     |
| DeepSeek 缓存分层 + 可解释路由      | `PromptCacheSlabBuilder` + `routeModel` + 动态思考预算          | 对自托管模型不暴露         |
| `edit_file` 五级级联 + 写前语法校验 | `tools/src/fs/editFile.ts`                                      | CC/Codex 均无写前校验      |
| Web 工具 SSRF 加固                  | `web/fetch.ts` DNS + 私网封锁                                   | 成熟                       |

## 补短地图（按主题）

### ① 弱模型可靠性（最高杠杆）

- 🔴 防跑飞机制默认不触发：`maxIterations` 默认 8，`getRunawayPromptInterval`
  在 `maxAttempts<=10` 时返回 `Infinity`；无重复/无进展检测。【已修复：
  `LoopProgressGuard` + 恒有限 runaway 间隔 + 默认 24 轮】
- 🔴 provider 只认原生 `tool_calls`，本地模型文本输出被静默丢弃。【已修复：
  `parseTextToolCalls`（Hermes 标签 + JSON 围栏）+ `<thinking>/<reasoning>` 变体】
- 压缩是 240 字符机械截断。【已修复：`buildSemanticCompactionSummary`
  fast-model 语义摘要，失败退回机械摘要】
- 降级粘性不恢复；`repairAttempts` 跨历史累计。【已修复：降级带两次尝试的
  冷却窗口后回到质量通道；`countRepairAttemptsForCurrentTask` 将修复预算
  限定在当前任务】

### ② 可信（声誉风险：宣传大于现实)

- 🔴 `bash` 绕过全部路径/密钥防护，auto 模式可读 `.env`、写工作区外。【已修复：
  `CommandPathAnalyzer` + PermissionEngine 路径边界/protectedPaths 检查】
- 无任何 OS 级沙箱（无 seatbelt/bubblewrap/landlock/seccomp）。【待办 P2】
- Windows 上 `.orbit/`、明文 checkpoint 备份世界可读。【已修复：工作区
  `.orbit/` 上 icacls 继承型 owner-only ACL（`ensurePrivateDirectory`）；
  checkpoint 备份 AES-256-GCM 静态加密（密钥走 DPAPI/keychain 凭据库），
  旧明文可读、篡改跳过，`security.encryptCheckpoints` 可关】
- `redactSecrets` 只认 5 类密钥。【已修复：新增 AWS/GitHub/Slack/JWT/npm/
  Google/Stripe/环境变量赋值 8 类检测】
- Rollback 非原子写；checkpoint 对二进制文件损坏、无多文件原子回退。【待办】

### ③ 表桌级功能缺口

- 无 apply_patch/多点编辑、无后台 shell、`read_file` 无行号前缀。【待办】
- WebUI markdown：勘察结论部分过时——块级渲染（表格/标题/列表/引用/代码块
  折叠复制/diff 着色/语法高亮）已存在；真实缺口是行内斜体/删除线与 h4-h6。
  【已修复：行内补齐 `em`/`del`/下划线斜体，标题扩展到 h6】diff 审查
  no-op（`showDiff`）。【已修复：`DiffView.renderPlain` 列 0 unified diff
  经 `file_diff` 事件流入浏览器会话（终端回合同样广播），审批面板真红绿
  着色；hunk 级选择性接受仍是 TUI 独有，Web 端整文件接受/回滚】
- MCP 仅 tools（无 resources/prompts/sampling），OAuth 仅 client-credentials。
  【已修复：resources → 每服务器 `read_resource` 只读工具；prompts →
  `/mcp__server__prompt` 斜杠命令（补全+参数映射）；PKCE authorization-code
  （`orbit mcp login`，refresh token 进加密凭据库）。sampling 仍缺（待办）】
  超时硬编码 30s。【已修复：`mcpServers.<name>.requestTimeoutMs`
  （1s–600s）贯通 stdio 与 Streamable HTTP 两条传输链路】

### ④ 主平台 bug

- 🔴 `grep` 在 Windows 解析盘符错误、JS 兜底用字面匹配。【已修复：
  盘符容忍解析 + 正则兜底 + 相对路径归一化】

### 勘察修正（2026-07-26 复核）

- **多端只读观察已存在**：`ReplController` 发 `ui_turn_started/completed`
  （source: terminal），`WebUiEventStream` 桥接 `eventBus.on("*")` 广播全部
  事件，客户端 `handleOrbitEvent` 对终端回合走 `createStreamingTurn` 流式
  渲染。审计所述 409 实为回合期间对**写操作**的正当拒绝，非观察缺失。
- 结论：审计的 UI 层判断以抽样为准，动手前先核对代码现状（markdown 与
  观察两项均被高估）。
