# Orbit 工作区界面设计提案

以 3.0.0 为基线，主界面是 macOS Safari 中的本地工作区，Safari 扩展和终端是同一项工作的另外两个入口。本文给出改版方向和验收条件。[用 Safari 打开交互样稿](workspace-review.html)

![桌面样稿在同一窗口展示对话、写入后审查和对应文件的差异](workspace-review.png)

## 从一次真实操作看问题

用系统 Safari 打开项目自带的预览，在 1440 × 900 和 390 × 844 下查看同一个示例会话。会话里有一个写入后的文件审查请求和两条排队消息。

| 用户想做的事          | 当前看到的界面                                                                                          | 改版决定                                                                                                           |
| --------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 看 Orbit 刚才说了什么 | 窄窗口里，长差异、两个审批按钮、两条排队消息和输入区同时占据会话下方，大部分对话在屏幕外                | 审查卡进入对应的对话位置，差异按需打开。底部显示当前状态和折叠的队列计数。用户正在读旧消息时提供「查看待审改动」。 |
| 决定是否接受改动      | 文件已经写入，标题和原因里有线索，按钮仍统一叫「允许」「拒绝」                                          | 写入前用「允许这次操作」「拒绝」，写入后用「保留改动」「回退本次改动」。卡片直接写明文件、时态和决定的后果。       |
| 检查具体文件          | 「变更」面板先列出五种发起审查的选项，文件列表在其下。主工具栏和详情页又各有一组 Safari、变更、运行入口 | 文件和验证结果排在详情首屏。「发起项目审查」迁到命令面板及新对话建议。对话中的具体入口直接定位到对应文件。         |
| 把网页选文带进来      | 工作区的 Safari 面板主要介绍如何设置扩展，实际交接发生在 Safari 工具栏                                  | 第一次使用时从输入框的「添加上下文」发现连接说明。实际选文、回填和来源确认留在 Safari，草稿编辑留在会话。          |

这些观察来自预览夹具，不能说明用户实际遇到各场景的频率。建议上线前找一位初次使用者和一位熟悉 CLI 的使用者，分别完成一次交接与审查，记录他们选错的按钮和找不到的入口。

## 界面围绕一个会话组织

- **左侧找回工作。** 两层结构足够容纳「项目 → 对话」。保留搜索、归档、新对话和折叠。会话行优先显示标题，等待我确认的会话用文字提示。完整路径通过披露控件查看。窄窗口从标题栏打开导航，返回原会话时恢复阅读位置。
- **中间完成工作。** 标题栏给出所属项目、会话名和「任务详情」。正文依次容纳指令、关键进度、需要人决定的事、结果。收到工具输出时合并同类活动，例如「已读取 3 个文件」，具体调用可展开。用户上翻时保持位置，新事件通过「回到最新」进入。
- **右侧检查证据。** 「查看差异」直接打开目标文件，「查看失败项」直接打开目标检查，「任务详情」打开上次使用的位置。文件、验证、执行记录和检查点共用一个面板。恢复文件和回退检查点分别说明作用范围。桌面允许边读边看，窄窗口用可关闭的单层详情，关闭后焦点和卷动位置回到原处。
- **底部表达下一步。** 输入框常驻。把文件、图片、Safari 选文归到「添加上下文」，已添加的来源仍可见、可移除。模型和权限保留可见摘要，高权限模式写全称。运行时把「加入队列」「立即引导」「停止执行」的作用写清楚，停止始终可达。队列折叠后保留计数，展开可编辑和移除。
- **设置管理长期选择。** 外观、语言、默认模型、权限策略与能力管理放在设置。当前轮次生效的权限始终在会话中可查。上下文用量平时放在详情，接近模型限制并可能影响本轮时才在对话里提示。阈值沿用运行时实际预算。

这套侧栏按内容层级组织，在窄窗口让出阅读空间，依据 Apple 对侧栏层级和 macOS 窗口缩放的建议。[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/sidebars)

## 四个决定交互是否可信的时刻

| 时刻                 | 用户看见                                                                                       | 操作与反馈                                                                                                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 运行中收到新指令     | 「正在读取文件」「已排队 2 条」，计数来自当前轮次                                              | 普通发送明确加入队列。立即引导另有具名入口。停止后先进入「正在停止」，收到终止事件才写「已停止」。                                                                   |
| 需要决定             | 写入前显示操作、目标与范围。写入后显示具体文件、差异入口和回退范围。缺少细节时直接展示已有原因 | 审批按当前请求 ID 提交一次。正在提交时禁用双击。拒绝执行、回退文件、扩大整个项目的权限分别使用独立文案。回退失败要保留错误和检查入口。                               |
| 断线或切换工作区     | 连接状态与执行状态分别呈现，例如「连接中断 · 上次状态：执行中」                                | 保留本工作区草稿，可继续编辑。断线时暂停发送和审批。重连先读取当前会话、队列和有效审批 ID，再恢复按钮，过期决定不能重放。                                            |
| 完成、失败或次日回来 | 在会话末尾留下一条结果，说明改了什么、验证通过什么、还欠什么                                   | 有改动时显示「查看文件」，检查失败时显示失败项和下一步，未运行的检查写「未运行」。重新打开同一会话应能找到原结果。仅有空闲状态时显示「就绪」，完成需要结束事件支持。 |

**Safari 交接。** 扩展弹窗先显示目标工作区和来源页面。选中的文本进入可编辑草稿。已有文字时提供「追加到草稿」「取消」并保留原顺序。表单回填先展示字段和值，再执行「填入已核对的内容」，最后报告实际填入数量。提交网页表单由用户在原页面完成。完整来源若需独立删除或跨重载保存，应先定义结构化草稿数据和旧纯文本草稿的读取方式。

**终端。** Web UI、Safari 扩展和 TUI 共用操作词汇。「排队」「引导」「停止」「回退」在三个入口中表达同样的后果。终端用一行状态和可展开的详情，长差异继续交给分页器。扩展聚焦来源与目标，对话全文和执行日志归会话所有。

## 视觉与 Safari 细节

- 保留 Orbit 猫标、灰绿底色和现有明暗主题。主操作使用现有深青色，琥珀色用于等待决定，错误使用红色。每种状态都有文字，差异保留加减号，品牌珊瑚点仅用于标志。
- 正文建议 16px、行高 1.6–1.7，正文列约 680–760px。文件路径和代码用等宽字体，聊天与操作使用系统 UI 字体及中文回退。正文、标题、辅助文字三档足够。段落用留白分组，边框优先用于输入和可操作区域。
- 保留用户对侧栏宽度、详情开合和主题的选择。只有会话与详情都能容纳可读内容时才分栏。窄窗口优先保留对话和输入，长差异在自身区域滚动。短窗口里审批操作可以滚动到达。窗口缩放不应改写用户的桌面偏好。
- 中文输入法组词期间，回车用于选词。非组词状态的 Enter 发送或排队，Shift+Enter 换行。所有主要动作可点击也可用键盘；Mac 提示显示实际可用的按键。逐项检查当前硬编码的 Ctrl 提示和 Safari 已占用的窗口级快捷键。
- 新审批出现时提示一次。用户正在打字或选择文本时保留焦点，显式点击后再定位审批。详情用 Esc 关闭。VoiceOver 朗读状态转换，连续输出按步骤合并；减少动态效果时取消非必要位移动画。

## 交付顺序与验收

| 顺序                        | 改动范围                                                                                               | 可复现的通过条件                                                                                                            |
| --------------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 一 · 先解决审批和小窗口拥挤 | 按现有 approval.kind 映射文案，正文放审查卡，底部保留状态、队列计数和定位；复用已有审批控制器和请求 ID | 在 390 × 844 同时放入长差异和两条排队消息。默认可读对话，待审入口始终可达，展开能看完整差异。断线及重复点击均不重复提交。   |
| 二 · 让结果有固定入口       | 调整工作台内容次序，具体文件、验证与失败事件可直接定位。保留检查点、任务计划、代理、运行日志和导出诊断 | 从会话结果一次点击可看到相关文件或失败检查。关闭详情、切换会话、回到窄窗口后能恢复位置。无验证数据时不会显示成功。          |
| 三 · 贯通 Safari 和 TUI     | 统一词汇、键盘提示与来源卡片。用简体中文、繁体中文和英语检查布局与朗读                                 | Safari 从网页选文追加至已有草稿，取消后原稿完整。审阅表单、部分回填、拒绝权限和断线均能得到明确反馈。终端同步出现对应状态。 |

实现入口在 Web UI 的 [页面结构](../../packages/cli/src/runtime/webui/WebUiPage.ts)、[审批控制器](../../packages/cli/src/runtime/webui/WebUiClientApproval.ts)、[工作台](../../packages/cli/src/runtime/webui/WebUiClientWorkbench.ts)、[事件路由](../../packages/cli/src/runtime/webui/WebUiClientEventRouting.ts) 和 [Safari 弹窗](../../editors/safari/popup.js)。三阶段分别跑对应的行为契约，同时保留现有设置、权限、队列与恢复能力。最终以系统 Safari 的亮暗模式、键盘、中文输入法、VoiceOver 和窄窗口实测验收。

交互样稿使用一条示例文档改动，可演练查看差异、保留或回退、断线时继续编辑、追加示例选文及折叠队列。底部场景切换器是设计评审工具。真实文件操作、模型执行、扩展通信、系统辅助功能及跨重载恢复在产品实现阶段验证。

样稿已在系统 Safari 的 1280px 和 390px 窗口走查审批、差异与草稿交接。另用 macOS 自带的 WKWebView 复核 320px 宽度、亮暗主题、断线禁用、草稿保留和模拟组词事件。人工 VoiceOver 与真实输入法验收仍需在产品界面执行。
